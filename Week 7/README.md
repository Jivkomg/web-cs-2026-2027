# Лекция 7: PHP и бази данни

Приемаме, че SQL вече ви е познат (`SELECT`, `INSERT`, `UPDATE`, `DELETE`, `JOIN`). Днес ще видим как PHP **изпраща** тези заявки към базата и как го прави **безопасно**.

---

## 1. Как PHP говори с базата

```
 Браузър ── GET /index.php ──► Apache ──► PHP ── SQL заявка ──► MySQL
    ▲                                      │                      │
    └──────────── HTML ◄───────────────────┘ ◄──── редове ────────┘
```

1. Браузърът иска страница.
2. PHP **се свързва** с базата и изпраща SQL заявка.
3. Базата връща **редове**. За PHP те са масиви.
4. PHP превръща редовете в **HTML** и го изпраща на браузъра.

> 💡 Браузърът никога не говори с базата директно. Паролата за базата и SQL заявките са само на сървъра.

---

## 2. Подготовка

**MySQL в XAMPP:** в `xampp-control.exe` пуснете **Apache** и **MySQL**.

**phpMyAdmin** е уеб интерфейс за базата: **http://localhost/phpmyadmin**. В XAMPP потребителят е `root`, без парола.

Най-бързият начин да създадете базата е таб **SQL** в phpMyAdmin: поставяте SQL-а и натискате **Go**.

```sql
CREATE DATABASE university CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE university;

CREATE TABLE electives (
    id INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(128) NOT NULL,
    description VARCHAR(1024),
    lecturer VARCHAR(128) NOT NULL
);

INSERT INTO electives (title, description, lecturer) VALUES
    ('Програмиране с Go', 'Да научим Go', 'Николай Бачийски'),
    ('АКДУ', 'Да завършим', 'Светлин Иванов'),
    ('Уеб технологии', 'Да научим уеба', 'Милен Петров');
```

> ⚠️ Използвайте **`utf8mb4`**, не `utf8`. В MySQL `utf8` е непълна версия на UTF-8: кирилицата работи, но емоджитата се чупят. `utf8mb4` е истинският UTF-8.

## 3. Свързване с PDO

В PHP има два начина за работа с MySQL: **PDO** и **mysqli**. Ще ползваме **PDO**: работи и с други бази (PostgreSQL, SQLite) със същия код.

Връзката се прави **веднъж**, в отделен файл, който всяка страница включва:

```php
<?php
// db.php: връзка с базата. Включва се с require във всяка страница.

$host = 'localhost';
$dbName = 'university';
$user = 'root';
$password = '';   // в XAMPP по подразбиране е празна

$db = new PDO(
    "mysql:host=$host;dbname=$dbName;charset=utf8mb4",   // DSN: къде е базата
    $user,
    $password,
    [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,        // при грешка: изключение
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,   // редовете са асоциативни масиви
    ]
);
```

```php
<?php
// index.php
require 'db.php';   // вече имаме $db
```

| Опция | Какво прави |
|---|---|
| `charset=utf8mb4` | Кирилицата се записва и чете правилно |
| `ERRMODE_EXCEPTION` | Грешна заявка спира скрипта с ясно съобщение, вместо да мълчи |
| `FETCH_ASSOC` | Ред е `['id' => 1, 'title' => '…']`, достъп с `$row['title']` |

> 💡 Ако промените нещо по връзката (друга база, парола), го правите на **едно** място.

## 4. Четене на данни

**Заявка без параметри:** `query()`.

```php
<?php
require 'db.php';

$electives = $db->query('SELECT * FROM electives ORDER BY title')->fetchAll();
?>
<ul>
    <?php foreach ($electives as $elective): ?>
        <li><?= htmlspecialchars($elective['title']) ?> (<?= htmlspecialchars($elective['lecturer']) ?>)</li>
    <?php endforeach; ?>
</ul>
```

| Метод | Връща |
|---|---|
| `fetchAll()` | **Всички** редове: масив от масиви |
| `fetch()` | **Един** ред, или `false`, ако няма повече |
| `fetchColumn()` | Стойността от първата колона на един ред: удобно за `SELECT COUNT(*)` |

```php
$count = $db->query('SELECT COUNT(*) FROM electives')->fetchColumn();   // 3
```

> 🔒 Данните от базата също се извеждат с **`htmlspecialchars()`**. Някой ги е въвел през форма, и там може да има `<script>`.

> 💡 Записът `foreach (…): … endforeach;` е същото като `foreach (…) { … }`, но се чете по-лесно сред HTML.

## 5. SQL injection: защо не слепваме заявки

Да кажем, че търсим дисциплина по име от формата:

```php
<?php
// ❌ НИКОГА ТАКА
$title = $_GET['title'];
$sql = "SELECT * FROM electives WHERE title = '$title'";
$rows = $db->query($sql)->fetchAll();
```

С `?title=АКДУ` всичко е наред. Но ако потребителят напише в полето:

```
' OR '1'='1
```

заявката става:

```sql
SELECT * FROM electives WHERE title = '' OR '1'='1'
```

`'1'='1'` е винаги вярно, и заявката връща **всички** редове. На форма за вход същото значи влизане **без парола**. С малко повече усилия атакуващият може да прочете други таблици или да промени данни.

🧪 **Демо:** `demo-sql-injection/index.php` има две полета за търсене: едното слепва заявката, а другото е с prepared statement (раздел 6). С `' OR '1'='1` първото връща всички дисциплини и показва изпълнената заявка, а второто не намира нищо. Само за локален компютър.

> 🔒 **Проблемът:** данните от потребителя стават **част от SQL кода**. Решението е те да се изпращат **отделно** от кода.

## 6. Prepared statements

Заявката се изпраща **с празни места** (`?` или `:име`), а стойностите отделно. Базата никога не ги чете като SQL.

**С `?`** (позиционни параметри):

```php
<?php
$stmt = $db->prepare('SELECT * FROM electives WHERE title = ?');
$stmt->execute([$_GET['title']]);
$rows = $stmt->fetchAll();
```

**С имена** (по-четимо при много параметри):

```php
<?php
$stmt = $db->prepare('
    INSERT INTO electives (title, description, lecturer)
    VALUES (:title, :description, :lecturer)
');

$stmt->execute([
    'title' => $title,
    'description' => $description,
    'lecturer' => $lecturer,
]);

$newId = $db->lastInsertId();   // id-то на новия ред
```

**Един ред по id:**

```php
<?php
$stmt = $db->prepare('SELECT * FROM electives WHERE id = ?');
$stmt->execute([$id]);
$elective = $stmt->fetch();   // масив или false, ако няма такъв ред

if (!$elective) {
    http_response_code(404);
    echo 'Няма такава дисциплина.';
    exit;
}
```

**Промяна и изтриване:**

```php
<?php
$stmt = $db->prepare('UPDATE electives SET title = ? WHERE id = ?');
$stmt->execute([$title, $id]);

$stmt = $db->prepare('DELETE FROM electives WHERE id = ?');
$stmt->execute([$id]);
echo $stmt->rowCount();   // колко реда са засегнати
```

> ⚠️ **Без кавички около `?`.** `WHERE title = '?'` търси буквално текста „?", а не параметър. Кавичките слага базата сама.
>
> ⚠️ **Параметрите са само за стойности,** не за имена на таблици и колони. `ORDER BY ?` не работи. Ако колоната идва от потребителя, проверете я срещу списък с позволени стойности.

> ✅ **Правило:** всяка заявка, в която има данни от потребителя, е **prepared**. Без изключения.

## 7. Грешки

С `ERRMODE_EXCEPTION` грешна заявка хвърля `PDOException`:

```php
<?php
try {
    $db = new PDO(…);
} catch (PDOException $e) {
    error_log($e->getMessage());   // в лога на сървъра, за вас
    http_response_code(500);
    exit('Базата данни не е достъпна. Опитайте по-късно.');   // за потребителя
}
```

> 🔒 **Не показвайте `$e->getMessage()` на потребителя** на истински сайт. Съобщението може да съдържа името на базата, потребителя или самата заявка. По време на разработка е полезно да го виждате, но на сървъра остава само в лога.

## 8. Форма, която записва: шаблонът POST → проверка → пренасочване

```php
<?php
// add.php
require 'db.php';

$errors = [];
$title = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $title = trim($_POST['title'] ?? '');

    // 1. Проверка на сървъра: JavaScript проверката може да се заобиколи
    if (mb_strlen($title) < 3) {
        $errors['title'] = 'Името трябва да е поне 3 символа.';
    }

    // 2. Запис само ако няма грешки
    if (!$errors) {
        $stmt = $db->prepare('INSERT INTO electives (title, lecturer) VALUES (?, ?)');
        $stmt->execute([$title, 'Неизвестен']);

        // 3. Пренасочване: браузърът зарежда index.php с GET
        header('Location: index.php');
        exit;
    }
}
?>
<!-- 4. Ако сме тук: първо отваряне (GET) или има грешки -->
<form method="post">
    <label for="title">Име</label>
    <input id="title" name="title" value="<?= htmlspecialchars($title) ?>">
    <?php if (isset($errors['title'])): ?>
        <p class="error"><?= $errors['title'] ?></p>
    <?php endif; ?>
    <button type="submit">Добави</button>
</form>
```

- **`$_SERVER['REQUEST_METHOD']`** казва дали страницата е отворена (`GET`) или формата е изпратена (`POST`).
- **При грешка** формата се показва отново, **с въведените стойности** (`value="…"`), за да не пише потребителят всичко наново.
- **`mb_strlen`** брои символи. `strlen` брои байтове, а в UTF-8 една кирилска буква е 2 байта: `strlen('АКДУ')` е 8.
- **`header('Location: …')` + `exit`** след успешен запис се нарича **Post/Redirect/Get**. Без него F5 след изпращане казва „изпрати формата отново?" и записва реда **втори път**.

> ⚠️ `header()` работи само **преди** да е изведен какъвто и да е HTML (дори интервал или празен ред преди `<?php`). Затова логиката е най-горе, а HTML-ът отдолу.

## 9. Добри практики

| Практика | Защо |
|---|---|
| Връзката е в **един** `db.php` | Промяна на едно място |
| Логиката е **най-горе**, HTML-ът отдолу | Четимо; `header()` работи |
| Проверката е **на сървъра** | JavaScript и HTML проверката може да се заобиколят |
| **Prepared statements** винаги | SQL injection |
| **`htmlspecialchars()`** при извеждане | XSS |
| Повтарящ се код → **функция** | Ако копирате, вероятно трябва функция |
| На истински сървър: **не `root`**, а потребител само с нужните права, и **истинска парола** | Ако сайтът бъде пробит, щетите са по-малки |
| Паролата за базата **не се качва в Git** | Хранилищата изтичат по-често, отколкото мислите |

---

## 10. Накратко: транзакции

Когато няколко заявки трябва да минат **заедно или никак** (например превод на пари: минус от едната сметка, плюс в другата):

```php
<?php
$db->beginTransaction();
try {
    // … няколко заявки …
    $db->commit();     // всичко минава
} catch (PDOException $e) {
    $db->rollBack();   // нищо не се записва
}
```

За днешната задача няма да ви трябват.

# Задача: Каталог на избираемите дисциплини

Работете на **итерации**: всяка надгражда предишната и завършва с работеща страница.

**Подготовка:** създайте базата и таблицата от раздел 2 и файла `db.php` от раздел 3.

---

### Итерация 1: Списък

- `index.php` показва всички дисциплини в **таблица**: име, преподавател, описание.
- Подредени са по име.
- Под таблицата пише колко са дисциплините общо.
- Ако няма дисциплини: „Все още няма дисциплини."

**Готово, когато:** виждате трите дисциплини.

---

### Итерация 2: Добавяне

- Добавете колона `created_at`, която пази **момента на добавяне** на реда. Направете го с SQL, така че базата да я попълва сама.
- `index.php` показва и датата на добавяне, във формат `16.11.2026 19:35`.
- Нова страница `add.php` с форма: име, описание, преподавател.
- **Проверка на сървъра:**
  - името е задължително, от 3 до 128 символа;
  - преподавателят е задължителен, от 3 до 128 символа;
  - описанието не е задължително, до 1024 символа.
- При грешка формата се показва **отново, с въведените стойности**, а до всяко грешно поле има съобщение.
- При успех: запис с **prepared statement** и **пренасочване** към `index.php`.
- В `index.php` има линк „Добави дисциплина".

**Подсказки:** `ALTER TABLE`, `DEFAULT CURRENT_TIMESTAMP`, `date('d.m.Y H:i', strtotime(…))`

**Готово, когато:** новата дисциплина се вижда в списъка с днешна дата, а F5 след добавяне не я добавя втори път.

---

### Итерация 3: Редактиране

- До всяка дисциплина в списъка има линк „Редактирай" към `edit.php?id=1`.
- `GET edit.php?id=1` показва формата, **попълнена** с текущите стойности.
- `POST edit.php?id=1` проверява данните **по същите правила** и променя дисциплината.
- Ако дисциплина с това `id` няма, страницата връща **404** и съобщение.

> 💡 Правилата за проверка вече ги имате в `add.php`. Не ги копирайте: изнесете ги във функция в отделен файл и я ползвайте и на двете места.
>
> 💡 HTML формите могат да изпращат само `GET` и `POST`. За промяна по-правилният HTTP метод е `PUT`, но той се праща само с JavaScript (`fetch`).

**Готово, когато:** промяната се вижда в списъка, а `edit.php?id=999` дава 404.

---

### Итерация 4 (бонус): Търсене и изтриване

- **Търсене:** поле над таблицата филтрира дисциплините по част от името **или** от името на преподавателя. Търсеният текст остава в полето.
- **Изтриване:** бутон „Изтрий" до всяка дисциплина.
  - Изтриването става с **`POST`**, не с линк (`GET`).
  - Преди изтриване браузърът пита „Сигурни ли сте?".

**Подсказки:** `LIKE` с `%`: `$stmt->execute(["%$search%"])`. За потвърждението: `onsubmit="return confirm('…')"` на формата.

> 🔒 **Защо не с линк?** `GET` трябва само да чете. Браузърите, търсачките и антивирусните програми понякога „отварят" линкове предварително, за да ги проверят, и така биха изтрили данни.

**Готово, когато:** „Петров" намира „Уеб технологии", а изтриването маха реда.
