# Лекция 1: Въведение в HTML

---

## 1. Какво е HTML?

**HTML** (HyperText Markup Language) е езикът, на който са изградени уеб страниците. Това е **език за маркиране**: с помощта на **тагове** той описва съдържанието и структурата на страницата. Таговете казват на браузъра как да покаже текст, линкове, снимки, видео и всичко останало.

> 🏠 **Аналогия:** HTML е като архитектурен план на къща: показва къде са стаите, вратите и прозорците и как е разпределено пространството.

### Трите езика на браузъра

| Език | Роля | Аналогия |
|---|---|---|
| **HTML** | Структура | Стените и стаите |
| **CSS** | Стил | Боята и мебелите |
| **JavaScript / PHP** | Функционалност | Електричеството и водопроводът |

### Първата уеб страница

Първата уеб страница е създадена от **Тим Бърнърс-Лий**, физик в **CERN**, и все още работи:

🔗 https://info.cern.ch/hypertext/WWW/TheProject.html

## 2. Как браузърът показва страницата

```
 Заявка ──► Отговор ──► Парсване ──► DOM ─┐
 (URL)      (HTML)                        ├──► Render tree ──► Layout ──► Paint
                         CSS ──► CSSOM ───┘
                         JavaScript може да променя DOM и CSSOM
```

| # | Стъпка | Какво се случва |
|---|---|---|
| 1 | **Заявка и отговор** | Браузърът изпраща заявка към URL адреса. Сървърът връща HTML документ с хедър `Content-Type: text/html`. |
| 2 | **Парсване** | Браузърът превръща байтовете в символи (според `charset`), разделя текста на тагове и **постепенно** изгражда **DOM** дървото (Document Object Model), докато данните пристигат. Междувременно изтегля CSS, JS и снимките, които открие. |
| 3 | **CSS** | Стиловете се превръщат в **CSSOM**. Изобразяването **изчаква** CSS. |
| 4 | **JavaScript** | Скриптовете могат да **спрат парсването** и да **променят DOM**. |
| 5 | **Render tree** | DOM + CSSOM се обединяват; остават само видимите елементи. |
| 6 | **Layout → Paint** | Браузърът изчислява размера и позицията на всеки елемент и рисува пикселите на екрана. |

> 💡 `<!DOCTYPE html>` превключва браузъра в **standards mode**.

## 3. Как се дебъгва HTML

- **F12** или **десен бутон → Inspect** отваря Developer Tools.
- **Ctrl + Shift + C** (на Mac: **Cmd + Shift + C**) включва режима за избор на елемент. Посочете с мишката нещо на страницата и то се осветява; кликнете и DevTools ви показва точно неговия HTML в таба **Elements**. Бутонът за същото е стрелката в горния ляв ъгъл на DevTools.
- В таба **Elements** можете да редактирате страницата на живо.

> ⚠️ Промените са само във **вашето локално копие** в браузъра. Сайтът не се променя. Ако презаредите, всичко се връща.

## 4. Разбор на пример: `first.html`

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <h1>Heading 1</h1>
</body>
</html>
```

### Стъпка 1: Заявка и отговор

Как браузърът разбира, че това е HTML, зависи от начина, по който отваряме файла:

- **Двоен клик от диска (`file://`):** няма сървър. Браузърът решава по разширението `.html`.
- **През сървър:** сървърът изпраща хедър `Content-Type: text/html`.
  - **Демо:** F12 → **Network** → презареждане → клик върху документа → **Headers**.

### Стъпка 2: Парсване → DOM

Таговете се четат отгоре надолу:

| Ред | Какво прави |
|---|---|
| `<!DOCTYPE html>` | **Не е HTML елемент.** Казва на браузъра да използва **standards mode**. Без него браузърът минава в **quirks mode**, който имитира грешките на браузърите от 90-те, за да не се чупят стари страници. |
| `<meta charset="UTF-8">` | Казва на браузъра как да превърне байтовете в символи. Стои рано в `<head>` нарочно: трябва да е в първите **1024 байта** на файла. С английски текст липсата му не се забелязва; **с кирилица се забелязва.** |
| `<html lang="en">` | Коренът на DOM дървото. Браузърите използват `lang` за предложения за превод и за пренасяне на думи. Екранните четци го ползват за правилно произношение. |

> 🇧🇬 Тъй като пишем на български, страниците ни трябва да използват `lang="bg"`.

**Полученото DOM дърво:**

```
html
├── head
│   ├── meta (charset)
│   ├── meta (viewport)
│   └── title
└── body
    └── h1
```

> 🧪 **Демо:** изтрийте таговете `<html>`, `<head>` и `<body>` от файла, презаредете и отворете **Elements**. И трите все още са в DOM, защото **парсерът ги добавя сам**. Сравнете с **Ctrl+U** (изходния код): файлът и DOM вече не съвпадат.
>
> **DOM е това, което браузърът е разбрал от файла ви, а не самият файл.**

📖 Какви грешки поправя парсерът: https://html.spec.whatwg.org/#parse-errors

### Основната структура

| Таг | Какво е | Вижда ли се? |
|---|---|---|
| `<html>` | **Коренът** на страницата. Всичко останало (текст, снимки, линкове) е вложено в него, като клони на дърво. | – |
| `<head>` | **„Склад" за информация за страницата:** заглавие, кодировка, връзки към стилове и скриптове. | ❌ Не (освен `<title>` в таба на браузъра) |
| `<body>` | **Съдържанието:** текст, снимки, заглавия, списъци. | ✅ Да |

## 5. Основни елементи: `second.html`

Един HTML елемент се състои от **начален таг**, **съдържание** и **краен таг**:

```html
<p>Това е параграф.</p>
<!-- ↑ начален   ↑ съдържание   ↑ краен -->
```

### Заглавия

`<h1>` е най-важното заглавие, `<h6>` е най-малко важното.

```html
<h1> This is heading 1 </h1>
<h2> This is heading 2 </h2>
<h3> This is heading 3 </h3>
<h4> This is heading 4 </h4>
<h5> This is heading 5 </h5>
<h6> This is heading 6 </h6>
```

> 💡 Избирайте заглавие според **важността**, а не според размера. Размерът се променя с CSS.

### Параграф

```html
<p>This is a paragraph.</p>
```

### `<span>` и `<div>`: несемантични контейнери

Те **нямат никакво значение**. Използваме ги, когато **няма подходящ семантичен елемент**.

| | `<span>` | `<div>` |
|---|---|---|
| Тип | **inline**, остава на същия ред | **block**, започва на нов ред |
| Кога | Искате контрол над част от текст | Искате контрол над група от елементи |

```html
<span> Inline text here. </span>
<div> Block content here. </div>

<div>This a large main division, with <span>a small bit</span> of spanned text!</div>
```

> 🔍 **Защо в Elements има текст в кавички?** Когато текстът е смесен с тагове, DevTools показва всяко парче текст като отделен **текстов възел**:
>
> ```
> <div>
>     "This a large main division, with "
>     <span>a small bit</span>
>     " of spanned text!"
> </div>
> ```
>
> `<div>`-ът има 3 деца: текст, `<span>`, текст. **Текстът също е възел в DOM.** Демо: изберете елемента и напишете `$0.childNodes` в Console.

### 🤔 Какво ще излезе?

```html
<div>Some <span>text that <div>I want</div> to mark</span> up</div>
```

<details>
<summary>Отговор</summary>

- **Изглед:** `I want` излиза **на отделен ред**, защото `<div>` е block елемент, дори когато е вътре в `<span>`.
- **Валидност:** кодът е **невалиден**. `<span>` може да съдържа само inline съдържание, а `<div>` е block. W3C валидаторът ще покаже грешка.
- **DOM:** браузърът **не** го поправя. В Elements `<div>` си остава вътре в `<span>`.

Сравнете с `<p>`: ако сложите `<div>` в `<p>`, парсерът **затваря** параграфа автоматично и DOM изглежда различно от файла.

</details>

### Списъци

**Номериран (`<ol>`):** редът е важен, например стъпки в рецепта.

```html
<ol>
    <li> First list item </li>
    <li> Second list item </li>
    <li> Third list item </li>
</ol>
```

**Неномериран (`<ul>`):** редът не е важен, например списък за пазаруване.

```html
<ul>
    <li> One list item </li>
    <li> Some list item </li>
    <li> Another list item </li>
</ul>
```

### Линкове

Линковете в HTML са **хипервръзки** към друг документ или URL.

```html
<a href="url">link text</a>                                       <!-- шаблон -->
<a href="first.html">first html</a>                               <!-- относителен път: файл до текущия -->
<a href="https://learn.fmi.uni-sofia.bg/">moodle</a>              <!-- абсолютен URL -->
<a href="https://learn.fmi.uni-sofia.bg/" target="_blank">moodle</a>  <!-- в нов раздел -->
```

### Атрибути

**Атрибутите** дават допълнителна информация за елемента. Пишат се в началния таг: `име="стойност"`.

| Атрибут | Пример | Какво прави |
|---|---|---|
| `href` | `<a href="...">` | Накъде води линкът |
| `target` | `target="_blank"` | Къде да се отвори линкът (`_blank` = нов раздел) |
| `src` | `<img src="...">` | Път (URL) до снимката. **Задължителен.** |
| `alt` | `alt="Shrek"` | Текст, който описва снимката |
| `lang` | `<html lang="bg">` | Език на съдържанието |

> 🔒 **Добра практика:** към `target="_blank"` добавяйте `rel="noopener noreferrer"`. Така новият раздел не може да управлява вашата страница и другият сайт не вижда откъде идва посетителят.

### Снимки

```html
<img src="images.jpeg" alt="Shrek">
```

- Снимката **не е част от HTML файла**. Браузърът я изтегля отделно от сървъра в момента на зареждане и я вмъква в страницата.
- Затова пътят в `src` трябва да остане верен спрямо страницата. Ако преместите снимката или страницата, браузърът показва **иконка за счупена снимка** и текста от `alt`.
- `alt` е важен и за **екранните четци**: това е, което незрящият потребител чува вместо снимката.

### Favicon: иконката в таба на браузъра

Favicon е малката иконка до заглавието в таба, в отметките и в историята. Добавя се с `<link>` в **`<head>`**:

```html
<head>
    <meta charset="UTF-8">
    <title>Моята страница</title>
    <link rel="icon" href="favicon.png" type="image/png">
</head>
```

| Формат | Пример | Бележка |
|---|---|---|
| **PNG** | `<link rel="icon" href="favicon.png" type="image/png">` | Най-лесният вариант. Квадратна снимка, например 32×32 или 64×64 px. |
| **SVG** | `<link rel="icon" href="favicon.svg" type="image/svg+xml">` | Остава остра при всякакъв размер. |
| **ICO** | `<link rel="icon" href="favicon.ico">` | Старият формат, поддържан навсякъде. |

- Пътят в `href` работи като при `<img>`: относителен спрямо страницата или пълен URL.
- Ако не посочите favicon, браузърът сам търси **`/favicon.ico`** в корена на сайта.
  - **Демо:** отворете страница без favicon през сървър, F12 → **Network**. Ще видите заявка за `favicon.ico` с грешка **404**.

> 💡 Браузърите **кешират** favicon-ите упорито. Ако сменихте иконката, а старата още се показва, добавете версия към адреса: `href="favicon.png?v=2"`. Новият адрес принуждава браузъра да я изтегли отново.

## 6. Семантичен HTML

**Семантичен HTML** означава да избираме елементи според това **какво е съдържанието**, а не как трябва да изглежда.

| Елемент | Какво казва |
|---|---|
| `<nav>` | „Това е навигация." |
| `<h2>` | „Това е заглавие едно ниво под основното." |
| `<button>` | „Това прави нещо, когато се активира." |
| `<div>` | **Нищо.** Просто кутия. |

Браузърът, екранните четци, търсачките и другите програмисти разбират значението само от тага.

### Защо има значение

- ⌨️ **Потребители с клавиатура** могат да стигнат до истински `<button>` с **Tab** и да го натиснат с **Enter**. `<div>`, който само изглежда като бутон, се прескача.
- 🔍 **Търсачките и режимът за четене** използват структурата, за да разберат кое е важно.
- 👩‍💻 **Другите програмисти** разбират структурата веднага, вместо да разгадават `<div class="top-thing-wrapper">`.

> ❓ **Значи ли това, че не можем да ползваме `<div>`?** Не. `<div>` е **последната възможност**, а не първата. Ако съществува елемент, който описва съдържанието ви, ползвайте него. Ако няма, `<div>` е правилният избор.

### Скелет на страница

```
┌──────────────────────────────────────────┐
│                 <header>                 │
├────────┬────────────────────────┬────────┤
│        │       <section>        │        │
│ <nav>  │  ┌──────────────────┐  │<aside> │
│        │  │     <header>     │  │        │
│        │  ├──────────────────┤  │        │
│        │  │    <article>     │  │        │
│        │  ├──────────────────┤  │        │
│        │  │     <footer>     │  │        │
│        │  └──────────────────┘  │        │
├────────┴────────────────────────┴────────┤
│                 <footer>                 │
└──────────────────────────────────────────┘
```

| Елемент | Значение |
|---|---|
| `<header>` (горе) | Въвеждаща част на страницата: лого, име на сайта, понякога основното меню. |
| `<nav>` | Блок с **основни** навигационни линкове. Не всяка група линкове е `<nav>`; той е за важните, като главното меню. |
| `<main>` | **Основното съдържание** на страницата. Само един на страница. |
| `<section>` | Тематична група от съдържание. Обикновено има **собствено заглавие**. |
| `<header>` в секция | Заглавната част на секцията, например заглавие и дата. |
| `<article>` | **Самостоятелно** съдържание, което би имало смисъл и ако го преместите на друг сайт: блог пост, новина, коментар. |
| `<footer>` в секция | Долната част на секцията, например автор или свързани линкове. |
| `<aside>` | Съдържание, свързано със страницата, но не основно: съвети, реклами, свързани статии. |
| `<footer>` (долу) | Долната част на страницата: контакти, авторски права, линкове. |

> 💡 `<header>` и `<footer>` не означават „горе" и „долу" на страницата. Те принадлежат на елемента, в който са. Страницата има своя двойка, секцията има своя.
>
> 💡 Позициите (nav вляво, aside вдясно) идват от **CSS**, не от HTML. Семантичните елементи описват **значение**, не място.

### `semantic.html`

```html
<header>…</header>
<nav>…</nav>
<main>
  <section>
    <h2>…</h2>
    <article>
      <header>…</header>
      <p>…</p>
      <footer>…</footer>
    </article>
  </section>
</main>
<aside>…</aside>
<footer>…</footer>
```
